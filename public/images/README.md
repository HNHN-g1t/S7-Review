# 画像素材の置き場

ここに置いたファイルは Vite がそのまま `dist/` へコピーします。
コード側は決め打ちのファイル名で参照しているので、同じ名前で保存してください。

| ファイル名 | 用途 |
|---|---|
| `title-1.webp` 〜 `title-6.webp` | タイトル画面のイラスト。起動時のサイコロの目 1〜6 に対応（600x1300） |
| `title.webp` | 目ごとの絵が読み込めなかったときの代わり（9:16 の古い絵） |
| `saika-01.png` | サイカ 通常（待機・連鎖） |
| `saika-02.png` | サイカ 焦り（危険領域に届いたとき） |
| `saika-03.png` | サイカ ボム成立（技名を叫ぶ〜ほめ言葉のあいだ） |
| `saika-10.png` | サイカ フィーバー中 |
| `saika-11.png` | サイカ フィーバー中にボム成立 |

末尾の数字は「0 と 2 がふつう、1 と 3 がボムを決めた瞬間」、
十の位は「0 が通常時、1 がフィーバー中」という対応です。
どの顔を出すかは `faceFor()` が一か所で決めています。

顔の5枚は正方形で切り出してください。表示は 63〜72px なので、
2倍の 144px 角あたりが目安です。今は 128px 角が入っています。

ファイルが無い場合は絵文字とプレースホルダ枠にフォールバックするので、
揃っていなくてもゲームは動きます。

## タイトル絵を WebP にしている理由

写真的なグラデーションが多い絵柄で、PNG は最も苦手とする種類です。
元の `tytle2.png` は 941x1672 の 2.4MB ありました。透過も使っていないので、
アルファを落として 600x1066 の WebP に落としています。

品質は 90 ではなく **84** を選びました。実際の表示幅（260px）まで
縮めて比べると、品質84で PSNR 38.2dB、品質90で 39.6dB。
どちらも目視で差がつかない領域で、容量は 188KB と 146KB。
42KB の差のほうが効くと判断しています。

```python
from PIL import Image

Image.open("元の画像.png").convert("RGB") \
    .resize((600, 1066), Image.LANCZOS) \
    .save("title.webp", "WEBP", quality=84, method=6)
```

顔の5枚は PNG のままです。128px 角で 30KB 前後と小さく、
輪郭のはっきりした絵柄なので PNG のほうが向いています。

## ファビコンは `public/` 直下

タブや iOS のホーム画面に出るアイコンは、この images/ ではなく
ひとつ上の `public/` に置いてあります。`index.html` から
ルート直下のパス（`/favicon.ico` など）で参照するためです。

| ファイル名 | 用途 |
|---|---|
| `favicon.ico` | ブラウザのタブ。16/32/48px を1本に束ねたもの |
| `icon-192.png` | Android・PWA |
| `icon-512.png` | Android・PWA の大きい側 |
| `apple-touch-icon.png` | iOS のホーム画面（180px 角） |

元絵は `31_SAINOME7_asset/fab01.png`（1254px 角）です。作り直すときは
次の2点に注意してください。

- **外周の白は透過にする。** 元絵は白地の上に角丸の絵が乗っているだけで、
  そのままだと暗色のタブで白い四角に見えます。四隅から塗りつぶし
  （floodfill）で外側だけ抜くと、絵の中の白いハイライトは残ります。
- **apple-touch-icon だけは白地で焼く。** iOS は透過部分を黒く塗るため、
  アルファを残すと角が黒くなります。

`icon-192` と `icon-512` は 192色に減色しています。輪郭の階調は保ったまま、
512px で 306KB から 87KB まで下がりました。
