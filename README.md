# S7-Review — 開発専用確認サイト

確認サイトの原本はこのリポジトリの main。ゲーム本体は [SAINOME-SEVEN](https://github.com/HNHN-g1t/SAINOME-SEVEN) で別管理します。今回は e1c99edc030a69ca011aedb878ad1dcee8718a90 時点の追跡ファイル（ソース・画像・音源・仕様書・検証スクリプト）を一式取り込みました。node_modulesとビルド生成物は含めません。

## 起動

Node.jsを用意し、このフォルダで実行します。

```sh
npm ci
npm run dev -- --host 127.0.0.1
```

表示されたポートの /review.html を開いてください（通常は http://127.0.0.1:5173/review.html）。最上段の先頭「ドット絵プロンプト工房」から独立ツールへ移動できます。続くキャラクター図鑑／ヒッサツメ図鑑／マップ／ストーリー進行表／本体へ反映は画面内で切り替えます。狭い画面ではタブ列を横スクロールできます。技図鑑単独は /skills.html、キャラクター図鑑単独は /enemies.html。

確認サイトのビルドは `npm run build:gallery`（出力dist-gallery）。通常の `npm run build` には開発専用ページを含めません。模擬戦はlocalhost/127.0.0.1専用で、初期消音・保存分離。Vercel（プロジェクト s7-review）には vercel.json で `npm run build:gallery`・出力 `dist-gallery` を指定して載せる。middleware.ts でパスワードの入力画面を出し、正しければ30日間通す（Vercel の Secret 環境変数 REVIEW_PASSWORD。未設定なら誰も通さない。2026-10-19 ユーザー判断）。正式URLは https://s7-review.vercel.app/review。

## ドット絵プロンプト工房

独立ツールは `/pixel-prompts.html`。複数の画風（8bit風〜現代ドット）、色数・寸法・陰影、連番の条件を選び、基準画像と連番アニメの指示文を一括作成・コピー・テキスト保存します。背景は白（初期値）・G255の純緑・グレー3段階・透明の単一選択。肌色／目の印象／顔の輪郭の忠実度は各項目で弱・中・強を選べ、初期値はすべて中です。画像は端末内の原寸プレビューにのみ使い、外部送信や画像生成API呼び出しは行いません。`build:gallery` 専用で、既存のパスワード保護を継承。通常のゲーム用ビルドには含めません。[使い方と制約](docs/pixel-prompts.md)。

## 続きの作業

S7-Reviewの変更はこのリポジトリへ保存してください。本体へ反映するときは、確認サイトの「本体へ反映」タブ、または [本体Actions](https://github.com/HNHN-g1t/SAINOME-SEVEN/actions/workflows/review-to-game.yml) を使います。GitHub書き込み権限のあるアカウントでログインし、checkで検証、prで専用PRを作りマージします。どのPCからでもブラウザーだけで実行できます。詳しくは docs/レビューから本体へ反映.md。元の運用資料を下に保存していますが、ゲーム本体のURL・配信設定・当時の変更履歴は参照用です。今回のコピー元はSOURCE_SNAPSHOT.jsonに記録しています。

## 456You!

ヒッサツメ図鑑に追加。上下左右でつながる4→5→6が光り、4から順になぞると、起点の縦1列・横1行を貫きます。FEVER中は隣接する列・行も加え、それぞれ2本。追加は右・下、盤面端では内側です。なぞった3個も消費します。スコアと保存分離した敵模擬戦で使用可能。既存ストーリーの習得順・進行セーブは変更しません。

図鑑の「模擬戦」から通常／「FEVERで試す」を切り替えられます。単独確認は `/enemy-practice.html?enemy=koitsume&skill=you456`（FEVERは `&fever=1`）。検証は `node scripts/check-you456.cjs`。

Mac等でファイル監視によりViteが再起動を繰り返す場合は、`node scripts/serve-review.cjs` で監視なしのローカル確認サーバーを起動できます。URLは http://127.0.0.1:5180/review.html 。コード変更後はこのサーバーを再起動し、画面を再読み込みしてください。5180番が使用中なら既存サーバーを止めずエラーで終了します。

## ルール

- ウォール2-2は、着地・消去後の盤面の最高セルで積み高さを判定し、9段以上で仕切り直す。成功回数は保持。5段以上のミッションで新しく作るNEXTは3の抽選重みを3から4へ上げ、4段以下へ戻ると従来値へ戻す。既に表示済みの組は変更しない。単独抽選の3は約43.48%→50.63%（組内7の再抽選後の最終比率とは異なる）。練習のお手本用の組と他教室・旧モードは従来の出目。回帰：`node scripts/check-wall22-lesson.cjs`。

- 盤面は 7列 × 14段
- 3つの「メ」が1組で落下する。形は **一列** と **L字4向き** の5種（出現率は一列50% / L字50%）
- 上下左右で隣り合うメの合計が **7** になると両方消える（**セヴン消し**）
- 着地したブロックは分解されない。**消去に巻き込まれた塊だけ**がバラバラになり、1マスずつ独立して落下する
- **ボム技**（すべてセヴン消しより優先。本体の目が 1 / 3 / 4 / 6 と重ならないので同時に成立する）
  - **スパ1ボム**: 1のメが上下左右に **5つ以上** つながる。**7つ以上で得点2倍**
  - **スラ3ボム**: 3のメが斜めに3つ以上そろうと、**その斜めのラインを盤面の端まで一気通貫**で消す。
    2方向が交差して **X字**になったら双方向へ効き、**得点3倍**
  - **スク4ボム**: 4のメが2×2の正方形になる。**その正方形につながっている4も一緒に消える**
  - **スト6ボム**: 6のメが縦か横に4つ以上並ぶと、**その行または列を端まで一気通貫**で消す。
    縦横が交差して **十字**になったら **得点3倍**
- **危険領域**: 盤面上部7段。ここでメを消すと得点2倍。到達すると**ニコニコメ**（2と5が交互に点滅する黒いメ）が5%で出現する
- **ニコニコボム**: ニコニコメを2つ以上くっつけると、盤面上のすべての2と5が一斉に消える救済技。
  **3つ以上つながっても扱いは2つのときと同じ**
- **フィーバー**: ゲージが満タンで発動し15秒継続。得点4倍、ボムが周囲1マスを巻き込む。
  ゲージは「FEVER」の5文字で、20%ごとに1文字ずつ点灯する。発動すると全文字が虹色に流れて光る
- **ゲームオーバー**: 最上段にメが置かれたら終わり。
  ただし**最上段の左右2マスずつは対象外**で、隅に乗っただけでは終わらない

消去の優先順位は **ニコニコボム > 各種ボム > セヴン消し**。

ニコニコメは1つのブロックに1つまでしか出ません。
また **ニコニコボム以外では絶対に消えません**。一気通貫はニコニコメを素通りし、
フィーバーの巻き込みからも外れます。くっついていないニコニコメは、
ニコニコボムが発動しても盤面に残ります。

### 消える前の演出

ボムが成立すると、消える直前に**消える範囲が光ります**。成立の最小形
（スク4なら2×2の正方形）はマスのすきまも埋めてひとつながりに光り、
巻き込まれるだけのマスはすきまを光らせずマスの中だけが同じ色で光ります。
どこまで消えるのかがひと目で分かります。最小形は、直前に置いたブロックに
重なるものが選ばれます。

**一気通貫で巻き込まれたマスと、フィーバーで巻き込まれたマス**は、
技の色に白を重ねて光ります。本体とは別に「巻き添えで消える側」だと分かります。

消えるときは、1マスにつき4〜8個の円が縦横斜めの8方向へ飛び散ります。
円は単色ですが、7色のパステルが混ざることで集合が虹色に見えます。

### ニコニコボムの発動演出

このゲームで最も派手な技なので、消える前に3段構えの間を置いています。

1. **1200ms の溜め** — くっついたニコニコメを中心にスポットライトが絞り込まれ、
   その外側は色が反転したうえで白と黒が激しく入れ替わります。
   同時に、高音から一気に低音へ落ちて尾を引く音が鳴ります
2. **600ms の完全静止** — 画面が止まり、間が空きます
3. **消去** — 盤面の2と5がすべて黒地に白メ／白地に黒メで反転点滅し、
   重いレーザーで撃ち抜くような音とともに消えます

スポットライトの外側は、透明な円に極端に大きい `box-shadow` を付けて作っています。
影の部分が円の外側そのものになるので、マスクを組まずに穴あきの層が作れます。
反転は白を `mix-blend-mode: difference` で重ねることで行っています。

### 得点

| | |
|---|---|
| セヴン消し | 消したメの数 × 100 × チェイン数 |
| ボム | ボムレベル × 1,000点（2チェイン以降は2,000点） |
| スパ1が7つ以上 | ×2 |
| スラ3のX字 / スト6の十字 | ×3 |
| 5個以上まとめて消す | ×1.5 |
| 危険領域で消す | ×2 |
| フィーバー中 | ×4 |

技ごとの倍率はその技のぶんにだけ掛かります。複数のボムが同時に成立した場合、
それぞれ別々に計算して合算します。

**レベルはセヴン消しの得点だけで上がります。** ボムの得点はスコアには入りますが、
レベルには影響しません。ボムは1発で万単位が入るため、混ぜるとレベルが跳ね上がって
落下速度が一気に上がってしまうためです。

## 操作（PC）

| キー | 操作 |
|---|---|
| ← / → | 左右移動 |
| ← / → を素早く2回 | その方向の端まで移動 |
| Space | 右回りに90度回転 |
| ↓ | 1マス落下 |
| ↑ | 一気に落下 |
| P | 一時停止 |

一気に落下させると、盤面のメの並びだけが数ピクセル沈んで戻り、着地の
手応えが出ます。動くのはメの並びだけで、スコアやHUD、盤面の枠は動きません。
縦方向の移動だけで、拡大縮小はしません。

操作中のブロックが落ちていく先の空セルは、うっすらとグレーで照らされます。
明るいところがゆっくり下へ流れ続けるので、着地点が分かりやすくなり、
盤面が平面的に見えるのも避けられます。

落下操作（↓・↑・上下スワイプ）は**1回の操作につきブロック1つ**にだけ効きます。
押しっぱなしのまま次のブロックが出てきても、指やキーを離すまでは効きません。

一時停止は画面左下（フィーバーゲージと♪ボタンの間）のボタンからも行えます。
一時停止中は「再開」で続きから、「はじめから」で最初からやり直します。

## 操作（スマートフォン）

盤面を指でなぞって操作します。

| 動き | 操作 |
|---|---|
| 横になぞる | 指の動きに合わせて1マスずつ左右移動 |
| 素早く横にはらう | その方向の端まで移動 |
| 下になぞる | 1マスずつ落下 |
| 素早く下にはらう | 一気に落下 |
| 素早く上にはらう | 一気に落下（弾き上げる感覚で落とす） |
| タップ | 右回りに90度回転 |

指を置いた場所からの総移動量でブロックの位置を決めているため、指の動きと
ブロックがずれません。最初に大きく動いた向き（縦か横）に操作が固定されるので、
横に払っているつもりの縦揺れを落下として拾うこともありません。

盤面上の指の動きはすべてゲーム操作として扱われ、ページのスクロールや
引っ張って更新は起きません。盤面のサイズは画面の高さからも上限をかけているため、
14段すべてが縦にスクロールなしで収まります。

回転は右回りの一方向のみ。一列は中央のマス、L字は2×2の中心が回転軸になります。回転中も落下は止まりません。

### デプロイ

Vercel の Git 連携で `main` への push を検知して自動デプロイします。
`vercel.json` でビルドコマンドとキャッシュを指定しています。

- `/audio/*` … BGMは同名で差し替える運用のため、10分キャッシュ＋裏で更新確認

`vite.config.ts` の `base` はルート配信前提で `'/'` です。
GitHub Pages のようなサブパス配信に戻す場合は `'./'` に変更してください。

音のボタンは3段階を順に回ります。**♫** BGMと効果音 → **♪** 効果音のみ → **×** 消音。

タイトル画面で **日本語 / English** を選べます。選択は localStorage に保存され、
次回もその言語で開きます。文言は `TEXTS` と `SAIKA_IDLE_LINES` / `SAIKA_PRAISE_LINES` /
`SAIKA_WORRY_LINES` / `BOMB_CALLS` に集約してあるので、英文を直すときはそこだけ見れば足ります。

スコアは下7桁を `0000000` 形式で常に表示し、まだ到達していない上位の桁は
背景に溶け込むグレーで置いています。桁数が変わらないので、スコアが伸びても
右隣のFEVERゲージが動きません。1000万以上は `SCORE` の右に黄色で千万の位を出し、
9で頭打ち（表示上限は 99,999,999）です。

7桁に増やしたぶんは文字を小さくせず、パネルの左右の余白と字間で吸収しています。
数字は tabular-nums で等幅なので、字間を詰めても桁の揃いは崩れません。

### 音まわり

ヒドイメ登場のプレスは `src/hidoimeCrushAudio.ts` の180ms合成音。丸い低域と正弦波の高域を重ね、136ms間隔でサイが潰れ始める瞬間に1段1音を鳴らします。空の段は無音。同時2音まで、音源バッファは再利用。消音・一時停止・やり直し・退出・非表示・音声中断で残音を停止し、音声起動前の音は後から再生しません。初期登場・追加波・大群・総力戦・ヒドイメ模擬戦で共通処理を使用。`npm run test:audio` で波形と再生管理・登場経路の回帰を実行します（聴感・実機確認とは別）。

効果音（セヴン消し・設置音・ボムの祝福音）は Web Audio API でコード内合成しています。

### 効果音の共通バス

効果音はすべて共通のバスを通ってから出力されます。

```
各効果音 → ゲイン → コンプレッサー(-10dB / 12:1) → 出力段(0.9) → destination
```

個々の音を `destination` へ直結すると、音を大きくしたぶんだけ足し算で波形が
振り切れ、スマホの小さいスピーカーでは割れて痩せて聞こえます。コンプレッサーで
頭を押さえると、そのぶん全体を持ち上げられます。最後の出力段0.9は、
音が重なった瞬間に1.0へ届くのを防ぐための逃げ幅です。

リミッター通過後の実測ピーク（1.0を超えると割れる）:

| 音 | ピーク |
|---|---|
| 設置音 | 0.62 → 下げた（下記「設置音の音量」参照） |
| セヴン消し | 0.81 |
| ボム | 0.78 |
| ニコニコ | 0.76 |
| ボム＋設置の同時 | 0.83 |

音を厚くするために足しているもの:

- **設置音** … 本体の三角波に、当たった瞬間の短いノイズ（バンドパス1.8kHz）を重ねる。
  ノイズがあると「置いた瞬間」の位置がはっきりし、音量を上げなくても手応えが出る
- **セヴン消し** … 完全5度下を薄く重ねて厚みを出し、矩形波の芯を短く差し込む。
  小さいスピーカーは低音が出ないので、倍音のある波形で輪郭を残す
- **ボム** … 低い正弦波（180→48Hz）の一撃を先頭に置く。
  きらめきだけでは高音ばかりで迫力が出ないため

### フィーバー中のBGM

フィーバー中は本編のBGMを止め、専用の曲に差し替えます。

曲は `public/audio/fever-bgm.mp3`（34.6秒）を本編と同じ `HTMLAudioElement` で流します。
当初は「よろこびの歌」を Web Audio で合成した仮のものでしたが、音源が用意できたので
差し替えました。フィーバーは15秒なので、1回のあいだに一周することはありません。

音量は `0.34`。本編の `0.32` と数字は違いますが、曲そのものの実効値が異なるため、
実際に耳へ届く大きさの差は **0.3dB** に収まっています（本編 0.0428 / フィーバー 0.0441）。
差し替えたときは、この実効値を測り直して合わせてください。片方だけが大きいと、
切り替わりで段差が出ます。

フィーバーが終わるときは、100ms ほどかけて音量を絞ってから止めています。
本編BGMへ戻る場面なので、ぶつ切りにすると切れ目が耳につきます。

BGMの切り替えは2つの `useEffect` に分けています。ひとつにまとめると、
`status` が変わるたびにフィーバーの曲が頭から鳴り直してしまうためです。

素材ファイルが要るのはBGMだけで、`public/` に置いたものは Vite がそのまま `dist/` へ
コピーするため、JSバンドルには含まれず個別に配信・キャッシュされます。

BGMを差し替えるときは **`public/audio/main-bgm.mp3`（本編）／`public/audio/fever-bgm.mp3`
（フィーバー中）を同じ名前で上書き**してください。
`v2` `v3` のようにファイルを増やすと、そのぶんリポジトリの履歴に音源が積み上がります。
同名で上書きすれば、最新版だけがチェックアウトされます。

開発中は `window.__sainome` に純粋なゲームロジック（消去判定、ボム判定、重力）が公開され、
ブラウザのコンソールから直接検証できます。本番ビルドでは除去されます。

### 地の色は2枚（通常＝暗い／フィーバー＝明るい）

地の色を暗いほうへ戻し、**明るい配色はフィーバー中だけ**に移しました。
メ（サイコロ）の色は一切触っていません。切り替えているのは `:root` の
トークンだけなので、サイノメの見え方はどちらの地でも同じです。

| | 通常時 | フィーバー中 |
|---|---|---|
| `--bg` | `#161a21` | `#e9edf4` |
| `--panel` | `#1f242d` | `#ffffff` |
| `--board-bg` | `#181c23` | `#9fabbd` |
| `--text` | `#eef2f8` | `#2b3444` |

通常時の地は、旧ダーク（`--bg #0d1014`）から全体を一段持ち上げました。
沈みすぎていたためで、メとの明度差は十分残るところで止めています。

#### 切り替えはトークンそのものを補間する

`@property` でトークンを `<color>` として登録し、`transition` を掛けています。
登録していないカスタムプロパティは文字列扱いなので、`transition` を書いても
途中の色が作られず、一瞬で切り替わります。

| | 時間 | 実測（`--bg` の赤成分） |
|---|---|---|
| 通常 → フィーバー | 380ms | 22 → 84（140ms）→ 233（240ms） |
| フィーバー → 通常 | **600ms** | 233 → 206 → 127 → 49 → 22（0/150/300/450/620ms） |

遷移は「行き先の状態」に書かれた長さが使われるので、戻りの600msは `:root`、
入りの380msは `:root.is-fever-theme` に書いてあります。

切り替えは `html` に `.is-fever-theme` を付け外しするだけです。`body` ではなく
`html` に付けているのは、画面をはみ出した部分にも同じ地を敷くため。

地を2枚にしたことで、ベタ書きのままだと破綻する箇所が3つ出たので
トークンに逃がしました。いずれも**明るい前提の色**でした。

- `--overlay-veil` … ゲームオーバーと一時停止の覆い。`rgba(246,242,251,.92)`
  のままだと、暗い画面の中で盤面だけが白く浮いた
- `--digit-off` … 点いていない桁と FEVER の文字。`#ded6ee` は暗い地の上では
  本文より**明るく**なり、消えているはずの文字がいちばん目立っていた
- `--hover-tint` … マウスを乗せたボタン

逆に、白のままでよかったものは触っていません。消失時の白黒反転、
ニコニコボムの白、メのハイライトは、どちらの地でも白が正解です。

### BGMの音量

効果音を立たせるため、さらに15%下げました。

| | これまで | いま |
|---|---|---|
| 本編・タイトル | 0.157 → 0.133 | **0.120** |
| フィーバー | 0.167 → 0.142 | **0.128** |

当初は 0.32 で、`0.7倍` → `15%下げ` → `10%下げ` と重ねてここまで来ています。

### 効果音の全体音量（1.5倍）

効果音はまとめて1.5倍にしました。出口の段を `0.9 → 1.35` にしています。

最初はリミッターのしきい値を上げて天井を持ち上げようとしましたが、
**しきい値を上げると小さい音がむしろ小さくなりました**。`DynamicsCompressor` は
しきい値から持ち上げ量（メイクアップゲイン）を自動で決めるので、しきい値を
上げると持ち上げが減るためです。しきい値は -10dB のまま触らず、
リミッターの後ろで一律に上げています。

1.5倍にするとボムの頭が1.0を超えるので、最後に**波形整形の天井**を置きました。
0.8 までは素通し、その先を tanh で寝かせて 0.98 に漸近させます。
リミッターをもう1枚重ねなかったのは、そこでもメイクアップゲインが掛かって
全体が持ち上がってしまうからです。

実測（出口のピーク、3回の中央値）:

| 音 | 変更前 | 変更後 | 倍率 |
|---|---|---|---|
| 設置 | 0.215 | 0.323 | **1.50** |
| セヴン1連鎖 | 0.289 | 0.433 | **1.50** |
| ボム | 0.733 | 0.946 | 1.29（天井で止めた） |

### フィーバーへの点火

ゲージが満ちてから **460ms** の点火を挟み、そのあとフィーバー本体が始まります。

最初は白を一枚かぶせて地の色の切り替わりを隠していましたが、
**白の明滅が画面のチラつきに見えました**。いまは白を使いません。

- 粒（32個）が、中心寄りの出発点から画面ぜんたいの行き先へ弾けて広がる
- 同じ間に、地の色がトークンの補間で暗→明へ満ちていく
- 中心から遠い粒ほど遅れて出るので、広がりが波として読める

出発点は行き先から中心へ65%寄せた位置です。全員が内側から外へ走るので、
画面が内側から弾けたように見えます。行き先の置き方は **R2列**（x と y に
別々の無理数）。片方を「index を素数で割った余り」にすると2つの進み方が
揃ってしまい、粒が斜め1本に並びました。

点火の開始とタイマーは `useEffect` を分けてあります。1つにまとめると、
`setFeverIgniting(true)` で同じ効果が再実行され、張ったばかりのタイマーが
後片付けで消えて、フィーバーが永遠に始まりませんでした。

### フィーバー中の背景

盤面の外側に、12色の円を 40 個散らします。ふくらんで瞬いてしぼむのを繰り返し、
途中に短い明滅を挟んで「はじける」感じを出しています。

色はグリーンとスカイブルーを重ねて入れてあり、寒色が全体の 58% を占めます。
`BURST_COLORS` をそのまま使うと暖色に寄るため、フィーバー専用の並びを持たせました。
周期は 1.3〜2.3 秒。以前の 2.6〜4.6 秒の半分で、瞬きの回転が倍になっています。

位置と大きさは起動時に一度だけ決めて固定します。毎回作り直すと、
再描画のたびに円が飛び回って落ち着きません。散らし方は乱数ではなく、
黄金比を足していく方式です。少ない数でも固まらずに散ります。

#### 処理落ちへの対策

当初は 102 個を `filter: blur(1px)` でぼかしていましたが、フィーバー中に
はっきりコマ落ちしていました。CPUを4倍遅くした環境での実測で
**58.5 → 39.7 fps**（-32%）です。原因は2つありました。

**1. 円のJSXを毎回作り直していた。** 位置や色は起動時に決まって以後
変わらないのに、親が再描画されるたびに全要素を作り直していました。
フィーバー中はゲージが100msごとに動くため、そのたびに生成と差分計算が走ります。
プロファイルでは、要素を作る `jsxDEV` だけで**全体の47%**を占めていました。
`FeverSparks` を `memo` で包み、props が同じなら丸ごと飛ばすようにしました。
修正後はJavaScriptのコストがほぼ消え、残りは描画と合成だけになっています。

**2. 数と大きさが、そのまま合成の負荷だった。** 円は1つずつが合成レイヤーに
なるため、枚数と面積が効きます。実測では数がいちばん効き、58個→40個で
秒間コマ数が3割上がりました。逆に大きさを上げると分かりやすく落ちます
（同じ40個でも、一回り大きくしただけで 56.8 → 46.5 fps）。

見やすさは**不透明度と塗りの広さで稼いでいます**。この2つは一度描いたものを
使い回せるので、大きさと違って合成の面積が増えません。`filter: blur()` も
やめて、中心から外へ薄くなる `radial-gradient` に置き換えました。にじみは
残りますが、要素ごとのぼかし直しが走らなくなります。

| | 修正前 | 修正後 |
|---|---|---|
| CPU 4倍遅く | 39.7 fps | **56.8 fps** |
| CPU 6倍遅く | 32.4 fps | **52.5 fps** |
| 円の数 | 102 | 40 |
| ぼかし | `filter: blur(1px)` | `radial-gradient` |

なお `will-change` の有無は実測で差が出ませんでした（32.4 / 32.0 fps）。
アニメーションしている要素はどのみち合成レイヤーへ上がるためです。

`z-index: 0` で敷き、スコア段やサイカ帯は `z-index: 1` で前に出しています。
**盤面（`.board-panel`）にだけは `z-index` を付けていません。** 付けると
新しい重ね合わせ文脈ができ、その中にいるタイトル画面（`z-index: 40`）が
外へ出られなくなって、スコア段のほうが前に来てしまいます。

### ゲームオーバー演出

確定した瞬間に**落胆の音「ヴェ〜」を鳴らしてから**、盤面を止め、
**上の段から下へ、数マスずつ灰へ沈めます**（1600ms）。
同じ段の中は順不同です。左から順に並べるとワイパーのように見えて、
「上から降りてくる」感じになりません。

灰にするのは**マス側だけ**です。以前は画面全体にも `grayscale` を掛けていた
ため、波が通ったマスには同じフィルターが二重に掛かり、そこだけさらに暗く
沈んで、処理が引っかかったように見えていました。全画面のフィルターは
負荷も大きいので外しています。

音はのこぎり波を2本わずかにずらして重ね、うなりで濁らせています。
音程を揺らす低速の正弦波を足してあり、一定に下がるだけにならないように
しています。ローパスを閉じながら落とすので、鳴り終わりはこもって沈みます。

刻みは最大 20 回ですが、マスがそれより少ないときは刻みも減らします。
常に 20 回に分けると途中で配り終えて、見た目には 1600ms より早く止まります。

沈め終わってから、**「ゲームオーバー」の文字が 400ms のあいだにバラバラに現れます**。
出る順番も入れ替えています。左から順に出すと打鍵しているように見えるためです。

文字は1つずつ span に切って動かしますが、読み上げと文字列の取り出しは
別に置いた `.sr-only` のテキストに任せています。切った span だけだと
行ボックスが分かれ、`innerText` に改行が入って文として読めなくなります。

### 設置音のタイミング

設置音は**「これ以上落ちられなくなった瞬間」**に鳴らします。

実際にブロックが固定されるのは、その次の落下タイミングです。固定まで待って
から鳴らすと、見た目より音が遅れて聞こえます。先に鳴らしておけば置いた手応えが
すぐ返り、**固定までのあいだに横へずらす余地はそのまま残ります**。
きわどい位置に滑り込ませる裏技として使えます。

実測では、音が鳴った時点で状態は `playing` のままで、直後に左を押すと
ブロックの列が動きました。

一気に落とした場合は着地の検知を通らないため、そのときは従来どおり
固定の処理側で鳴らします。二重に鳴らないよう、ブロックのIDで見分けています。

### 設置音の音量

設置音は毎手かならず鳴るので、他の効果音と同じ土俵に立たせると前に出すぎます。
出口の `master` を **0.28** に絞りました。

バスの入口でタップした実測ピーク（リミッターへ入る前の値）:

| 音 | ピーク |
|---|---|
| 設置音 | 0.430 |
| セヴン消し（1連鎖） | 0.497 |

設置音がセヴン消しの **0.87倍**で、狙いどおり「同じか、やや下」に収まりました。
絞る前は同じ測り方で約 1.54 あり、セヴン消しの3倍以上でした。

### 回転音「プリュン」

一瞬だけ上へ跳ねてから下がる、弾力のある短い音（520→900→600Hz、52ms）。
リミッター前のピークは **0.159** で、設置音の 0.62 に対して約1/4です。
回転は1手のあいだに何度も押すので、他の効果音と同じ音量にすると
置くまでずっと鳴りっぱなしで耳につきます。

回転が実際に通ったときだけ鳴らします。壁際で回れなかったときは鳴りません。

### ニコニコボムの円と粒

円は**終始正円**です。以前は `width: 150%` / `height: 150%` としていたため、
親（盤面）が縦長なぶん横長の楕円から始まっていました。`vmax` に変えて、
縦横が常に同じ長さになるようにしています。

円の縁には黒い四角の粒を 28 個貼りつけます。粒を置く輪は円と**まったく同じ
縮み方**をするので、粒は縁に乗ったまま中心へ引き寄せられ、
**円の内側（マスクの明るい部分）には決して入りません**。
粒の位置は親に対する % で置いてあります。親が正方形なので 50% がそのまま半径です。

実測では、終端で円が 92x92、粒の中心までの距離が 46.0px（＝半径ちょうど）でした。

なおニコニコボムは**バナーを出しません**。溜めの演出そのものが見せ場なので、
文字を重ねると画面が散らかります。技名はサイカのセリフだけで伝えます。

### 設置音のタイミング

**ブロックを動かしたのと同じ処理の中で鳴らします。** 以前は描画のあとの
`useEffect` で「もう落ちられない」を判定していたため、次の入力や落下まで
持ち越されて 60〜100ms 遅れることがありました。

実測では、DOM に着地が現れるより **9〜25ms 早く**鳴っています（平均12ms）。
音のほうが先に出るのは、React の再描画を待たずに鳴らしているためで、
耳と目のずれとしては1フレーム以内に収まります。

**設置音が鳴ってからも横へ滑らせられる区間はそのままです。** 実際に固定
されるのは次の落下タイミングなので、そこまでは動かせます。きわどい位置へ
滑り込ませる余地は残してあります。

### セヴン目音を先に出す・設置音とは重ねない

セヴン消しの音は、以前は「タメ → 発光 → 点滅開始」まで全部待ってから
鳴らしていました。揃った手応えが映像に置いていかれるので、
**消える直前のタメ（`PRE_CLEAR_WAIT_MS`）より前**へ移し、
そのタメを 80ms から **100ms** にしました。音が絵より 100ms 先に出ます。
ボムのタメ（240ms）は変えていないので、`BOMB_PRE_CLEAR_WAIT_MS` は
掛け算をやめて直に書いてあります。

あわせて、**消える手では設置音を鳴らしません**。設置音とセヴン目音が
同時に出ると音が濁り、どちらの手応えなのかも分からなくなるためです。
`clearKindOnLock()` が、その位置で固定したときに何が起きるかを先読みします。

#### 一度やらかした形：着地で黙ってしまう

最初は「消える手なら設置音を鳴らさない」とだけ実装しました。これだと
**着地の瞬間に何も鳴らず、最初の音は消去の処理が始まるまで出ません**。
実際に固定されるのは次の落下タイミングで、レベル1の落下間隔は 780ms
（`speed = max(180, 780 - (level-1)*45)`）。計測すると、揃う手では
**着地から 755 / 763 / 764ms 遅れて**最初の音が鳴っていました。
半拍まるごと黙るので、遅れて聞こえて当然です。

いま入っているのは、**着地の瞬間にセヴン目音のほうを鳴らしてしまう**形です。
設置音の代わりにセヴン目音が出るので、鳴る音は1つのまま、手応えは即返ります。

- 揃う手 … 着地でセヴン目音（1連鎖ぶん）。消去の処理では1連鎖ぶんを飛ばす
- ボム・ニコニコ … 発動前の溜めそのものが見せ場なので、着地は設置音のまま
- 揃わない手 … これまでどおり設置音

着地のあと横へずらして揃わなくなった場合は、固定の時点で設置音を鳴らして
締めます。滑り込みの余地（上の「設置音のタイミング」）はそのままです。

計測（描画上ブロックが止まったフレームを0msとする）:

| | 最初の音まで |
|---|---|
| 直す前・揃う手 | 755 / 763 / 764ms |
| 直したあと・揃う手 | **−17ms**（音のほうが1フレーム先） |

### AudioContext の出力レイテンシ

`new AudioContext()` を既定のまま作ると出力バッファが大きめに取られ、
鳴らした瞬間より一拍あとに音が出ます。`latencyHint: 'interactive'` を
渡して最短側に寄せました。操作に紐づく音しか鳴らさないので、
安定性より応答を取っています。

### BGMの先読み

`new Audio()` を再生の直前に作ると、そこから mp3 を取りに行くため
出だしのひと呼吸が無音になります。マウント直後に `getBgm().load()` と
`getFeverBgm().load()` を呼び、**タイトルを出している間に読み込ませます**。

実測では、ページを開いてから 270ms で両方の mp3 を要求し 280ms で取得まで
終わっていました。スタートを押す頃には手元にあります。

### タイトルBGMが最初の1回だけ鳴らなかった件

ブラウザは、ページを開いてから一度も触られていないうちは音を出させません。
これはどのページでも同じで、避けられません。なので「最初に触った瞬間」に
鳴らし始めるようにしていましたが、**iPhoneでは音ボタンを一周させないと
鳴りませんでした**。

原因は拾っていたイベントです。`pointerdown`（指が触れた瞬間）を見ていましたが、
iPhone（WebKit）は指で触れた瞬間の `pointerdown` を「ユーザー操作」とみなさず、
指を離した `touchend` と `click` でしか音の制限を解きません。パソコンのマウスでは
`pointerdown` でも解けるので、手元の確認では鳴っていました。音ボタンを押すと
鳴ったのは、ボタンが `click` だからです。

いまは `touchend` / `click` / `pointerup` / `keydown` を拾い、音ボタンを押したのと
同じことを画面には出さずに行います。音ボタンの表示は変わりません。

- タイトル曲はその場で鳴らす
- 本編とフィーバーの曲は、無音のまま一度だけ再生して止めておく。iPhone は
  操作の最中に一度でも再生した音源しか、あとから自由に鳴らせないため
- 最初に触ったのがスタートボタンなら、タイトル曲は鳴らさない（本編と一瞬重なるため）

### 設置音の先回り（着地の約100ms前）

自然落下で着地するときは、次の1段がいつ来るかが分かっています。
そこで「あと1段で着地する」位置に来たら、着地の少し前に設置音を予約します。
iPhone は鳴らしてから実際に音が出るまでに時間が掛かるので、先に出すと
絵とそろって聞こえます。

- 横へずらす・回すなどで位置が変わったら、予約を取り消して計算し直す
- **着地後に横へ滑らせられる仕様はそのまま**。鳴らす時刻を前へずらしただけ
- 指で下へ送って着地させた場合は、操作そのものが着地の合図なので先回りできず、
  これまでどおり着地の瞬間に鳴る

予約の早さ `LOCK_SOUND_LEAD_MS` は 85ms です。100ms にすると、着地の描画が
落下の刻みより少し遅れるぶん、実測で 114〜128ms 先になっていました。
85ms での実測は **99 / 101 / 103 / 104 / 105ms 先**（セヴンの着地も 107ms 先）です。

### 落下ガイドの色

ガイドは暗い灰（`#2f3d52`）をマスに重ねる作りで、明るい地では沈んで見えますが、
暗い地では暗いマスの上に暗い色を重ねることになり、ほぼ見えていませんでした。
色をトークン `--guide` にして、通常時は明るい灰（`#c3cde0`）を重ねてマスを
持ち上げ、フィーバー中は元の暗い灰に戻します。濃さの揺らぎはそのままです。

### 回転音（3つの候補から「ころっ」を採用）

回すたびに鳴る、さりげなく小さい操作音です。候補を3つ用意し、
`ROTATE_VARIANT` を書き換えるだけで入れ替わるようにしてあります。

| 候補 | 音 | 作り |
|---|---|---|
| **koro**（採用） | ころっ | 木の小さな粒が2つ、28ms差で長3度上へ。サイコロが一面ぶん転がった感じ |
| poko | ぽこ | 丸い木琴を一打ち。音程が少しだけ下がって丸く聞こえる |
| puni | ぷに | 三角波をやわらかく少しだけ持ち上げる、ゴムを押したような粒 |

1つ前の「ぷぃっ」は 1.3〜1.8kHz の正弦波に1オクターブ上（2.6〜3.5kHz）を重ねていて、
小さくても甲高く、何度も聞くと耳に刺さりました。3つとも基音を 600〜900Hz に下げ、
上の帯域は木琴の倍音（基音の約2.76倍）をうっすら足すだけにしています。
スマホで埋もれない明るさは倍音に持たせ、耳に痛い純音は使いません。

音量は候補ごとに合わせてあり（`ROTATE_TRIM`）、どれも出口のピーク約0.16です
（設置 0.323 / セヴン 0.433 の半分ほど）。

#### 鳴るタイミング

回転は「指を離した瞬間」に決まります（離すまでタップかスワイプか分からないため）。
計測すると、音は指を離してから **0.3ms** で鳴らし始め、盤面の絵が変わるのは
**15〜23ms** 後でした。コードの上では音のほうが先に出ています。

それでも遅れて聞こえるのは、iPhone が音を実際にスピーカーから出すまでに掛かる
時間のためです。ここは減らせるところだけ減らしました。

- 立ち上がりを 1ms の打楽器の形にした。音程やふくらみで始まる音は、耳が
  「鳴った」と感じるのが遅れる
- 回転音だけリミッターを通さず直接出す。リミッターは頭を押さえるために
  約6msの先読みを持っていて、通すとそのぶん遅れる。回転音は小さく
  音割れの心配がないので迂回できる

### フィーバー中のセヴン目音（コーラス＋リバーブ＋サステイン）

フィーバー中だけ、セヴン目音に次の3つを足します。どれも「浅く」が狙いです。
深くすると輪郭がぼやけて、連鎖の粒が聞き分けられなくなります。

- **サステイン** … 粒の長さを3.2倍に伸ばし、音程の落ち方を浅くする
  （通常 0.55倍まで落とすところを 0.82倍まで）
- **コーラス** … 18ms と 25ms の遅延を、0.9Hz と 1.3Hz でゆっくり揺らして重ねる（ウェット0.34）
- **リバーブ** … 減衰ノイズで作った1.6秒の残響を浅く重ねる（ウェット0.26）。
  こもらないよう、たたみ込む前に 320Hz 以下を削る

残響の素材は重いので、AudioContext ごとに1つだけ作って使い回します。
実測で、1連鎖の鳴っている長さ（-40dB まで）は 通常 110ms → フィーバー 400ms。

### 難易度：落下の速さの上がり方と、着地後の猶予

**① 毎レベル同じ「割合」で速くする**

以前は1段の間隔を毎レベル 45ms ずつ縮めていました。同じ「幅」で縮めると、間隔が短い後半ほど
1レベルの差が大きくなり、Lv13→14 で一気に 23% 速くなる壁ができていました（Lv15 で下限）。
いまは毎レベル 0.93倍（体感 7% ずつ速く）にして、どのレベルでも上がり方をそろえています。

| Lv | 以前 | いま |
|---|---|---|
| 1 | 780ms | 780ms |
| 10 | 375ms | 406ms |
| 14 | 195ms | 304ms |
| 20 | 180ms（下限） | 196ms |
| 下限に届く | Lv15 | Lv22 |

**② 着地後にずらせる時間を、落下の速さと切り離す**

以前は着地のあと「次の1段の刻み」で固定していたので、ずらせる時間が落下の間隔と同じになり、
速いレベルでは 0.18秒しかありませんでした。いまは、着地してから**最低 0.4秒**
（`LOCK_GRACE_MS`）は必ずずらせます。

- 猶予は最初に着地した時刻から数え、ずらしても延びない（いつまでも粘れないように）
- 猶予が切れる瞬間にタイマーで固定するので、刻みを待って延びることはない
- 落下の間隔が 0.4秒より長いレベル（Lv1〜9）は、これまでどおり次の刻みで固定
- ↓で送って固定するのは、これまでどおりすぐ固定

実測（何も触らず着地させたとき）:

| Lv | 1段の間隔 | 着地から固定まで |
|---|---|---|
| 1 | 780ms | 約765ms |
| 10 | 406ms | 400ms |
| 14 | 304ms | 400ms |
| 20 | 196ms | 400ms |

### 余韻の効いたボム音・回転音2倍・虹ボムの待ち時間1.5倍

- **ニコニコボム** … 破壊音のあとに、明るい五音の粒を降らせ（約1.6秒、だんだんまばらに）、
  下に和音を約2.2秒伸ばす。**フランジャー**（数msの遅延をゆっくり揺らして戻しを掛ける）と
  コーラス・リバーブを通すので、うねりながら長く光る。鳴っている長さ（-40dBまで）520ms → **2280ms**
- **虹ボム** … 後半に「チュルルル」。2つの音をすばやく行き来しながら5度ほど駆け上がり、
  最後の音を約1.2秒響かせる。コーラス・リバーブ・軽いフランジャー付き。350ms → **1730ms**
- **回転音** … 2倍の大きさに（出口のピーク 0.144 → 0.287）。設置音と同じくらい
- **虹ボムの「使う？」** … 3秒 → **4.5秒**。輪のゲージはこの長さをかけて減るので、そのままゆっくり進む。
  1秒ごとの刻み音は5回になる。実測でゲージ4.5秒、自動で「使わない」になるまで約4.47秒

### 設置音だけ 40ms 早める

着地の音をそろえたあと、設置音がやや遅く感じたので、**設置音だけ**さらに 40ms 早めました
（`LOCK_SOUND_EARLIER_MS`）。セヴン目音は着地の 20ms 後のまま、着地後に横へずらせる区間も変えていません。
実測（着地の絵を0msとして）: 設置音 −22〜−23ms、セヴン目音 +13〜+17ms。

### ボムの線を波線にして点滅させる

- スラ3・スト6 の一直線を、揺れを強めた**ランダムな波線**にした（本線 0.1マス・2本目 0.15マスの揺れ）
- スパ1・スク4・スラ3・スト6 の**本線を 20ms 点灯・20ms 消灯で点滅**させる。消えている瞬間に、
  後ろの2本目の波線と点々・にじみが見えて、線が震えているように見える。点滅は線を描き終えてから始まる
- セヴン消しの線は点滅させない（これまでどおり）

### ニコニコボム：ひとりぼっちの黒も一緒に発動

ニコニコボムが発動したとき、つながっていない**ひとりぼっちのニコニコメも共に発動**し、
それぞれ**自分と周囲8マス（3×3）**のメを巻き込んで消します。

- 発動の引き金は、これまでどおり2つ以上くっついたニコニコメ。ひとりぼっちだけでは発動しない
- スポットライトはくっついた塊に当て、点滅と震えはひとりぼっちも含めた全部のニコニコメに掛ける
- 確認: くっついた2つ・盤面の2と5・ひとりぼっちの周囲9マスが消え、関係ないマスは残る。
  ひとりぼっちだけの盤面では発動しない

### 着地の音の間合い（設置音とセヴン目音をそろえる）

着地で鳴る音（設置音か、揃う手ならセヴン目音のどちらか一方）は、**どちらも着地の絵から
20ms 後**にそろえて鳴らします（`TOUCHDOWN_SOUND_AFTER_MS`）。

それまでは、設置音は着地の約100ms前に鳴っていて早すぎ、セヴン目音は約20ms前でした。
先回りの予約（`LOCK_SOUND_LEAD_MS`）は残してありますが、予約の時点で「着地の絵が出るまであと何ms」を
計り、音そのものは AudioContext の時刻で着地に合わせて置くようにしています。
操作（↓・横すべり・回転・一気落下）で着地させた場合も、描画のぶん（約15ms、`LANDING_PAINT_LAG_MS`）を
足して同じ位置に合わせます。

実測（着地の絵を0msとして）:

| 着地のしかた | 鳴った位置 |
|---|---|
| 自然落下・設置音 | +16〜+20ms |
| 自然落下・セヴン目音 | +16〜+19ms |
| ↓で送った着地・設置音 | +12〜+18ms |

連鎖などで消えるときのセヴン目音は、消える流れの頭から 120ms 後に鳴らします（80ms からさらに 40ms 遅らせた）。

### セヴン目音の間合い（80ms 遅らせ）

着地の先回りや消去のタメより前に鳴らしているぶん、絵に対して少し早すぎたので、
鳴り始めを **80ms** 後ろへずらしました（`SEVEN_SOUND_DELAY_MS`）。
呼び出す時刻は変えず、音の予定（AudioContext の時刻）だけを遅らせているので、
他の音や絵の段取り、遅れた音を捨てる判定には影響しません。
実測で、呼び出してから鳴り始めるまでちょうど 80ms です。

### セヴン目音を消えた数で華やかに

一度に消えた数が多いほど、上へ駆け上がる粒が増え、最後の一音が長く伸びます。

| 消えた数 | 音 | 最後の一音 | 実測（-40dBまで鳴っている長さ） |
|---|---|---|---|
| 2〜3個 | ポリュン | ― | 120ms |
| 4〜5個 | ティラリラーン（4粒） | 0.55秒 | 470ms |
| 6〜9個 | 6粒 | 0.9秒 | 740ms |
| 10個〜 | ティラララララーン（8粒） | 1.4秒 | 1100ms |
| フィーバー中の10個〜 | 同じ＋コーラスとリバーブ | 1.4秒×1.6 | 1460ms |

駆け上がりは長3和音を積み上げた並び（ド・ミ・ソ・ド…）なので、どこで止めても明るく終わります。
最後の一音は音程をほとんど落とさずに伸ばし、1オクターブ下を薄く重ねて厚みを足しています。

### ニコニコボムの溜め（紫・白・黒の幕と、押し寄せる黒い粒）

- **黒い粒** … 64粒を内と外の2重の輪にして、画面の外寄り（中心から 46〜92vmax）から
  狙いの縁まで加速しながら一気に詰める。来る途中は進む向きに伸びた筋、着いたら丸い粒。
  黒だけだと暗い盤面に溶けるので、紫の細い縁取りを付けている
- **幕** … 白い地で覆うのをやめ、半透明の紫・白・黒を 120ms ずつ順に叩く。
  穴が狙いへ閉じていく。半透明なので、積み上がった盤面は透けて見えたまま
- **縁** … 大きいところから一気に締まり、最後は紫と白で光る

#### 来るぞ来るぞ（くっついたニコニコメの点滅と震え）

溜めの 1.2秒のあいだ、くっついたニコニコメ同士を白黒で交互に点滅させます。

- **だんだん速く** … 切り替えの間隔を 220ms から 0.8倍ずつ詰め、最後は 25ms まで速める（1.2秒で19回）
- **交互に** … 隣り合うメは位相を逆にしてある（市松の偶奇で決める）ので、片方が白いとき片方は黒い
- **プルプル震える** … 30ms 刻みで細かく揺らし、振れ幅を 0.3px から 2.6px までだんだん強くする

白黒は `filter: invert` の切り替えです。ニコニコメは暗い地に白い目なので、反転すると
白地に黒い目になります。震えは `transform` だけで動かすので、2つのメに掛けても軽い。
溜めが終わると点滅と震えはピタッと止まり、そのまま完全に静止する「間」に入ってから弾けます。

#### 軽くするためにやったこと

以前は「白を `difference` で重ねて外側を反転」「9999px の影を白黒に切り替え」
「円の幅と高さを縮める」の3つで作っていて、毎コマ描き直しと配置の計算が走っていました。

| | 直す前 | 直したあと |
|---|---|---|
| 配置の計算（溜めの1.15秒、CPU 1/4） | 58〜59回 | **2回** |
| メインスレッドの処理全体 | 583〜659ms | **427〜447ms**（約3割減） |

ただし、最初の作り直しでは逆に重くなりました。粒ごとの値（向きや距離）を
アニメーションの中で参照していたため、64粒ぶんが毎コマ計算し直しになり、
スタイル計算が 88ms → 207ms に増えていました（粒を消すと 45ms に戻ることで特定）。
いまは次のように、動きの中から粒ごとの値を追い出しています。

- 粒の向きは、外側の要素の**止まった回転**で持たせる
- 動きは出発距離の違う**4つの帯**ごとに、値を決め打ちしたキーフレームにする
- 幕は穴の大きさを動かさず、**狙いに穴を開けた幕を一度だけ塗って、拡大→等倍へ縮める**
- 3色は**3枚の幕の不透明度**を順番に切り替える

どれも描き直しの要らない動かし方（`transform` と `opacity`）です。
この計測は描き直しの負担（画面への塗り）を含んでいないので、反転の合成と
巨大な影をやめたぶん、実機ではさらに軽くなっているはずです。

### 遅れた効果音は鳴らさない

処理が詰まると、効果音を鳴らす処理そのものが予定より遅れて走ります。
絵のほう（CSS のアニメーション）は処理が詰まっても先に進むので、遅れて鳴った音は
「ワンテンポずれた音」に聞こえます。ずれた音を鳴らすくらいなら鳴らさないほうが
気持ちよいので、**予定から 120ms 以上遅れた音は捨てます**（`SFX_LATE_LIMIT_MS`）。
120ms は、耳と目が「同じ出来事」とみなせるずれの上限の目安です。

遅れの測り方:

- 指やキーの入力 … 入力が起きた時刻（`event.timeStamp`）から
- 自然落下 … その1段を刻むはずだった時刻から
- 設置音の先回り … 予約した時刻から
- 消去の流れ（セヴン目・ボム・ニコニコ・落ちたあとのコトッ）… 直前の待ちが
  予定よりどれだけ遅れて戻ってきたか

確認: ふつうに遊んだ12秒では捨てた音 0。設置音の予約をまたいで 700ms 処理を
止めると、その設置音は鳴らさずに捨てられた。

### 有効範囲の軌道

消える範囲を、線がサッと走ってなぞって見せます。盤面の上に SVG を1枚重ね、
座標はマス単位（`viewBox 0 0 7 14`）で描いています。

| 消え方 | 線 |
|---|---|
| セヴン消し・スパ1・スク4 | 消える範囲の**輪郭**をひと筆でなぞる。スク4なら四角を、左上の角から時計回りに一周 |
| スラ3 | 端から端まで**斜めに一本**。両端のマスから少し突き抜ける |
| スト6 | 端から端まで**横（縦）に一本**。一気通貫で巻き込む範囲まで含めて引く |
| ニコニコボム | 出さない（専用の溜め演出があるため） |

- 線は 200ms で走りきり、先頭には白い光が駆け抜ける
- 本来の線は、セヴン消しなら点滅が終わるまで、ボムなら弾けて300ms経つまで残る
- **フィーバー中のボム**は、広がった範囲の輪郭を金色の線で別に出す。本来の線より
  **300ms遅れて2回点滅しながら**現れ、**200ms遅れて消える**ので、外へ波及したことが順に読める
- にじみは `filter: blur` ではなく、太く薄い線を下に敷いて作る

#### 色と手描きの質感

- **セヴン消しの線は目の色の仲間に寄せる**。足して7になる目どうしは同じ色の仲間なので、
  1と6はピンク、**2と5はパープル**、3と4はグリーン。一度に別の仲間が消えるときは、
  仲間ごとに分けてそれぞれの色でなぞる。盤面で沈まないよう、メの色より少し明るくしてある
- **手描き風に崩す**。辺をおよそ0.45マスごとに刻み、刻み目を線と直角の向きへ少しだけ揺らしてから
  曲線でつなぐ（`sketchPath`）。角も曲線の中に入るので丸くなる。揺れは種から決め打ちに作るので、
  描き直しても線が変わらない
- **2本目の線**。細く薄い線を、揺れ方を変えて重ね、40ms 遅れて走らせる。わずかな食い違いが手描きらしさになる
- **にじみ**は、太く薄い線を2段（幅0.62と0.3マス）重ねて作る。`filter: blur` は使わない
- **点々**。2本目の線に沿って点を散らし、線を描き終えたところで浮かび、またたきながら少しずつ流れる

線は出すときに一度だけ作って持っておき、描き直しのたびに計算し直さないようにしています。
スク4を消す1.3秒の処理量（CPU 1/4、3回平均）は 直す前 875ms / 直したあと 861ms で、増えていません。

輪郭は、塗られたマスの辺のうち隣が塗られていない辺だけを集め、時計回りにつないで作ります。
一直線上の途中の点は省いて角だけ残すので、線がなめらかに走ります。

**SVG は盤面のマスより後ろ（最後の子）に置いています。** 市松は
`.board-cell:nth-child(even)` で塗っているので、マスより前に置くと偶奇がずれて、
線が出るたびに市松全体が反転してしまいます。

確認: セヴン（2×1の輪郭）、スク4（四角）、スラ3（斜め1本）、スト6（横1本）、
フィーバー中のスク4（四角＋広がった範囲の金の輪郭）をそれぞれ実際に消して描かれることを見た。

### フィーバー突入音「テューン！」

点火の粒が広がる 460ms のあいだ駆け上がり、フィーバーが始まる瞬間に着地します。

- **テュー** … わずかにずらした鋸波2本を 196→784Hz へ上げながら、共鳴を強めた
  ローパス（Q7）を 500→4200Hz へ開く。共鳴が音程と一緒に上がるので母音のように聞こえる
- **ン！** … ハ長調に9度を足した明るい和音（正弦波中心で刺さらない）と、
  130→58Hz へ沈む短い胴鳴り
- 着地のあとは、フィーバー中のセヴン目音と同じコーラスとリバーブでふわっと残す

### 虹ボムのあとに消えた段が一瞬映る件

飛ばし終えた直後、吹き飛んだはずのメが元の位置に戻って見えていました。
飛ばす絵を先に外してから 320ms 待ち、盤面から実際に消すのは呼び出し側に
任せていたためです。そのあいだ、消える前の盤面がそのまま描かれていました。

いまは「盤面から消す」「飛ばす絵と光の波を外す」を同じ瞬間にやり、320ms の待ちもやめました。
コマごとに上9段を数えた実測で、直す前は**最大57個のメが約270ms（18コマ）**映っていたのが、
直したあとは **0コマ** です。

### 起動時のサイコロ

アプリを立ち上げたら、まず画面の真ん中に大きなメが1つ出ます。タップで振ると
0.72秒転がって1〜6の目で止まり、0.52秒見せてからその目のタイトル画面に移ります。

- 文字は出しません。メの下で **👆 がトン、トンと叩く動き**でタップを促します
  （読み上げ用の説明だけ `aria-label` に残しています）
- **このタップがBGMの開始スイッチ**を兼ねます。振った瞬間に音の制限を解き、
  タイトル曲を鳴らし始めます。iPhone は指を離した `click` でしか音の制限を
  解かないので、`onClick` で受けています
- 振るのは**立ち上げるたびに一度だけ**。出た目は保存せず、次に立ち上げたら
  また振ります。コンティニューやタイトルへ戻るときには触らないので、
  同じ起動のあいだはずっと同じタイトル画面です
- タップした瞬間に **「コロコロコロっ」と転がる音**が鳴ります。明るい五音（ソ・ラ・シ・レ・ミ）から
  選んだ木の粒を、転がりが遅くなるのに合わせて間隔を 45ms → 約110ms と広げながら打ち、
  止まる瞬間（0.72秒）に少し大きめの「コトッ」と小さな跳ね返りで締めます
- **オープニング曲は、目が止まって転がる音が鳴り終えてから**始めます（止まってから 140ms 後）。
  曲は目ごとに `TITLE_BGM_SRCS` に並べてあり、いまは6つとも同じ曲です。曲ができたら差し替えるだけで、
  出た目に応じた曲が流れます
- 曲を鳴らすのはタップの外（止まってから）なので、iPhone で鳴らせるよう、タップの中で
  その目の曲を無音で一度だけ再生して止めておきます
- 確認（タップを0msとして）: 転がる音の粒 5〜579ms（9粒）、コトッ 725ms、跳ね返り 795ms、
  **オープニング曲の開始 871ms**。それより前には鳴っていない
- 目ごとのタイトル絵は `TITLE_IMAGES` に並べてあります。いまは6つとも同じ絵で、
  仮に**タイトル画面の左上に出た目の数字**を出しています。
  `title-1.webp` 〜 `title-6.webp` が揃ったら差し替えて、数字は外します
- ゆくゆくはタイトル曲も目ごとに6曲にする予定です

確認したこと: 起動直後は無音でサイコロだけ → タップ直後にタイトル曲が鳴る →
出た目とタイトルの数字が一致 → 一時停止からタイトルへ戻っても同じ数字 →
ゲームオーバーからコンティニューしてタイトルへ戻っても同じ数字 →
立ち上げ直すともう一度振る。

### 虹ボム：範囲を9段に・光の波・外へ押し広げて散る

**範囲** … 上から9段（危険領域の7段＋その下の2段）に広げました。
`RAINBOW_ROWS = DANGER_ROWS + 2` として、危険の判定とは別に持っています。
危険状態に入る高さは変えていません。広げたのは消す範囲だけです。
実測で、光る段は 0〜8 の9段、発動後に残るのは下の5段（各7個）でした。

**範囲の見せ方** … 以前はマスごとに白黒を乱数の位相で `steps` 点滅させて
いました。隣り合うマスがばらばらに反転するので**市松模様のチラつき**になり、
見ていて気持ち悪かったので、やめました。いまは:

- 白黒の反転をやめ、白い光を「重ねる」だけ。地の色もメの色も残る
- 値を「段の番号」にして、同じ段はそろって光り、段ごとに70msずつ遅れて波が下へ流れる
- `steps` ではなく `ease-in-out` で、明るさがなめらかに満ち引きする
- 光は `::after` の `opacity` だけで動かすので、描き直しが起きない

メの色を白黒に塗り替えなくなったので、`Die` の「塗りをCSSに任せる」判定から
`mono` を外しています。外し忘れると、範囲内のメが無色になります。

**爆発** … 範囲の中心から外向きに、2段階で動かします。

1. 押し広げ（0〜22%）… 全員がそろって外へ膨らむ。まだ回さない
2. 散る（22〜100%）… 回りながら一気に外へ抜ける

中心から遠いメほど遠くへ飛ぶ（距離 0.55〜1）ので、陣形そのものが膨らんで
見えます。以前は「上へ抜けるほうが消し飛ばした感じが出る」として上向きに
寄せていましたが、外へ広がる動きにするため寄せを外しました。

### タイトル画面の音ボタンと自動再生の解除

タイトルの絵（`.title-screen`）は `position: absolute; inset: 0; z-index: 40` で
盤面ごと覆うので、**HUDの音ボタンと一時停止ボタンはその下に隠れます**。
実測でも音ボタンの座標に `elementFromPoint` すると `.title-actions` が返り、
タップが通りませんでした。

これが問題になったのはタイトルBGMを足してからです。ブラウザの自動再生制限で
`play()` は「一度も操作していないページ」では弾かれます（失敗は握りつぶして
いるのでエラーも出ません）。タイトルにスタート以外の操作が無いと、
**解除する機会がないまま初回は必ず無音**になります。

直し方は2つ入れました。

1. **タイトルの下段にも音ボタンを置く**（`.title-sound`）。3列グリッドの左枠に
   `justify-self: end` で入れ、右の説明ボタンと鏡合わせにしています。
   スタートの中心は 393px 幅で 196px（画面中心 196.5px）、360px 幅で 180px
   （同 180px）と、置いても中央のままです。
2. **タイトルにいるあいだの最初の操作を拾って鳴らし直す**。`pointerdown` と
   `keydown` を window で1つずつ見て、止まっていれば `playTitleBgm()` を呼びます。
   音ボタンでも、言語の切り替えでも、絵を触っただけでも解けます。

実測（393x659）:

| 操作 | title-bgm |
|---|---|
| 開いた直後・無操作 | 停止 |
| 絵をタップ | 再生（0.7秒） |
| 音ボタンで🎵→🔇→🎶と一周 | 🎶に戻った時点で再生 |
| スタート | 停止し、main-bgm が再生 |

### 音ボタンの3状態

🎵 = BGM＋効果音 / ♪ = 効果音のみ / ✖️ = 両方オフ。押すたびにこの順で回ります。
以前は BGM 入りを `♫` にしていましたが、小さな丸ボタンの中では `♪` と
見分けがつきませんでした。

### ボムが出る直前の点滅

ボムは光らせて見せたあと、**400ms のあいだ盤面を止めて対象を点滅させて**
から発動します。

点滅は、そのメの色と**色相を180度回した反対色**を 110ms で入れ替えます。
同系色で明滅させるより、どのマスが対象なのかが一目で分かります。

| メ | 本来の色 | 反対色 |
|---|---|---|
| 1・6 ピンク | `#FC6DAC` | `#6DFCBD` |
| 2・5 パープル | `#8B46D2` | `#8DD246` |
| 3・4 グリーン | `#43AE39` | `#A439AE` |

**フィーバーで巻き添えになったマスだけは、6色（3色＋その反対色）を
回します。** 本体と区別がつき、広がった範囲がどこまでかも分かります。

なお内部の `swept` には一気通貫の巻き込みも入っているため、そのままでは
通貫部分まで6色になってしまいます。フィーバー分だけを別に控えて
判定しています。

### タイトル画面のBGM

`public/audio/title-bgm.mp3`（62.4秒）を、タイトルにいるあいだだけ流します。
スタートを押すと止まって本編へ、タイトルへ戻るとまた鳴り出します。

音量は `0.32` で本編と同じ。曲そのものの実効値もほぼ同じ（0.1336 / 0.1338）で、
耳に届く大きさの差は **0.0dB** です。差し替えるときは実効値を測り直して
合わせてください。片方だけ大きいと、スタートを押した瞬間に段差が出ます。

起動時に3本とも読み込みます。押してから読み込むと、出だしが無音になります。

### 音の切替アイコン

**🎶（BGM+SE）→ 🎵（SEのみ）→ 🔇（無し）** の3段階です。

`🎵` はもともと「音符1つ」の絵文字なので、`🎶`（2つ）と並べると
鳴っている量がそのまま音符の数になります。

以前使っていた `♪` は絵文字ではなく文字記号（U+266A、Extended_Pictographic
ではない）で、絵文字と並ぶと線が細く小さく浮いていました。`♪` `♫` には
絵文字表示そのものが存在しないため、絵文字でそろえるならこの組み合わせになります。

スピーカーの `🔊` / `🔉` も検討しましたが、18px では波の本数の差が潰れて
見分けられませんでした。

### ニコニコボムの咆哮・虹ボム頻度の本番化・左回転

### 敵への命中・多重再生（2026-10-13）

- SEは操作／演出／敵の行動／敵への命中／敵の撃破／デタラメの実ダメージ／白フラッシュ／イチニサンダーの8系統。BGMは従来どおり別のaudio要素で、タイトル・マップの0.7秒切替も維持する。
- チャンネルはミックス系統であり同時発音数ではない。命中・撃破・敵の行動を別コンプレッサーにし、重なった音同士が同じ圧縮処理で埋もれにくくする。既存の音は毎回独立した音源で鳴らし、連打で前の音を上書きしない。
- デタラメは消去の合図とは別に、実ダメージの白フラッシュを再開する瞬間に「キュパッ」を鳴らす。命中した生きた目の段数を集計し、1イベント最大8声・専用音全体で同時16声。無地の段への命中は鳴らさない。
- 専用PCMはコンテキストごとに1個共有。1声0.22秒以下、音程を少しずつ変えて重ね、イベントの音量を発音数の平方根で抑える。上限超過でも先行音は切らず、過剰な追加音を遅れて再生しない。専用コンプレッサーと既存の最終リミッターを通す。
- 専用音は一時停止・無音切替・画面非表示・再戦／終了・音声コンテキスト中断で停止。復帰時に古い音をまとめて鳴らさない。検証は `npm run test:audio` と `npm run test:anchi`。
