# どのPCからでもレビューを本体へ反映する

入口：[Reviewから本体へ反映](https://github.com/HNHN-g1t/SAINOME-SEVEN/actions/workflows/review-to-game.yml)

PCにGit・Node.js・Codexを入れなくても、ブラウザーから実行できます。ゲーム本体への書き込み権限があるGitHubアカウントでログインしてください。レビューサイトを閲覧する権限だけでは書き込めません。サイト内にトークンは保存しません。

1. S7-Reviewにコード・仕様をコミットする。Web編集は https://github.dev/HNHN-g1t/S7-Review 。ブラウザーのローカルなメモは、チャットへのコピー等で要望を反映してからコミットする。
2. 上の入口から **Run workflow** を押す。Branchは **main**。`review_ref` は通常 **main**。
3. まずmode **check** で差分・ビルドを確認。反映する場合はmode **pr** で実行する。
4. 成功すると本体に `review-sync/...` ブランチとPRが作られる。実行結果にあるPRを確認して **Merge pull request** すると、本体のmainへ反映する。本体の公開は従来のVercel設定に従う。

GitHubの設定でActionsのPR作成が禁止されている場合も、検証済みの専用ブランチはpushする。実行結果の比較リンクで **Create pull request** を押してからマージする。Actions自体が無効なリポジトリでは、所有者がActionsを有効にする必要がある。

## 対象と競合

対象は `src/`・`public/`・`docs/`・`scripts/`・`tests/`・package.json・package-lock.jsonの、レビュー側で変わった分だけ。Vercel設定、middleware、公開URL、認証設定、ルートのREADME/AGENTS/CLAUDE、Actionsワークフロー、引き継ぎログは移植しない。既存の本体側設定を守る。恒久的な仕様はdocs内の個別資料に保存する。

初回はSOURCE_SNAPSHOT.jsonのコピー元コミット、以後は本体の.review-sync-state.jsonに記録した前回同期地点との差分を使う。本体の最新mainへ **3方向マージ** し、本体で別途進んだ変更を保つ。同じ箇所が競合した場合、ファイルを上書きして成功扱いにせず停止する。Actionsのsummaryとartifact `review-sync-report` で対象・競合を確認する。checkだけでは本体へpushせず、prもmainへ直接pushしない。

ビルドや検証で失敗した場合もPRは作らない。検証ジョブは読み取り権限のみ。専用ブランチへpushする別ジョブは、検証済みパッチだけを扱い、レビュー側のコードを実行しない。

## ローカルPC・エージェントで競合を直す場合

本体リポジトリで未保存の変更がない状態にして実行する。

```sh
git switch main
git pull --ff-only origin main
node scripts/sync-review.cjs --plan
node scripts/sync-review.cjs --prepare
```

--planは差分レポートだけ、--prepareは専用ブランチで差分を適用する。競合時は `git status` のファイルを直し `git add` してから `node scripts/sync-review.cjs --finalize`。npm ci、本番・確認用ビルド、test:story、test:anchi等を実施する。検証済みブランチをコミットし `git push -u origin HEAD`、GitHubから本体mainへのPRを作る。`--publish` はActionsの独立したpublishジョブ用で、同じ作業ツリーで続けて呼ばない。

検証：`node scripts/check-review-sync.cjs`（独立Gitリポジトリを作り、並行変更保持・日本語仕様書・除外・専用ブランチpush・競合停止を検証）。
